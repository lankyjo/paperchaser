    Create tests/parity.spec.ts — one spec driving the torture fixture, three assertion groups per run:
    1. preview vs print projection: `page.goto('/?fixture=invoice-torture')`, wait for `#print-root`, assert the logo renders — `await expect(page.locator('img.document-logo')).toBeVisible()` and its naturalWidth > 0 (the torture fixture's logo is an inline data-URL SVG, so this needs no network) — then fullPage screenshot; `page.emulateMedia({ media: 'print' })`, fullPage screenshot; normalize both to 794px; pixelmatch with threshold 0.1 and includeAA false; assert diff fraction below the calibrated constant (default 0.01; calibrated in task 2).
    2. print projection vs PDF: `page.pdf({ format: 'A4', printBackground: true })`; rasterizePdf to 794px; compare each PDF page against the corresponding vertical slice of the print screenshot; assert per-page diff fraction below the calibrated constant. This is the ROADMAP SC3 parity contract.
    3. pagination + watermark/logo band analysis + baseline sanity:
       - assert `pdfDoc.numPages >= 2` for the torture fixture (the 18-item fixture is sized to paginate — this is what makes the per-page checks meaningful);
       - per-page watermark analysis (the harness-side evidence ADR 0002 criterion (b) cites): for each rasterized PDF page, crop the watermark band — the horizontal strip at top 40% +/- 15% of page height spanning full width (covers the rotate(-30deg) text) — and count pixels within the watermark's blended color range (the fixture's dark text color at opacity 0.15 over the white/light page background ≈ rgb(217,217,217) for near-black text, tolerance +/- 25; if the rendered text color is not near-black, compute the blend from it during calibration). Assert page 1's count >= a calibrated floor AND page 1's count > 3x the max count across pages >= 2 — this proves the watermark renders in the real page.pdf() output on page 1 and that Chromium does NOT repeat a single absolutely-positioned element across paginated pages (the measured first-page-only behavior ADR 0002 records);
       - per-page logo analysis: on page 1, crop the company-header band (top ~12% of page height, full width) and count pixels within the fixture logo's brand color (#1d4ed8, tolerance +/- 20); assert >= a calibrated floor — the logo is a solid-color mark, so the population is deterministic and proves the logo survives into the PDF;
       - baseline sanity: assert the committed golden tests/fixtures/invoice-torture.preview.png (when present) is not blank — non-white pixel fraction > 0.01 — and is 794px wide (Pitfall 5: a 100%-white baseline must fail the suite, or the parity tests "pass" against a wrong baseline forever);
       - calibration note: the watermark/logo band floors and the page-1/pages>=2 ratio are constants set in task 2 from measured distributions. If the watermark-blend range proves ambiguous against page >= 2 table content during calibration, fall back to the page-1 floor only (presence proof) and record in ADR 0002 exactly what the bands prove — the ADR must never claim more than the measured evidence.
    On any mismatch, write the diff image(s) to tests/artifacts/ for the failure artifact upload.

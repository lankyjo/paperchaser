# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope:** Templates (TEMP-01/02/03), Branding (BRND-01..07), PDF surface (PDF-01..06), Print preview (BUIL-10). Proves screen == print == PDF while rendering is cheap. Phase 3 is the **render bench** — NOT the Phase-4 three-pane builder. The bench exists to exercise templates/branding/page sizes/print preview against the parity harness.

## Spacing Scale

**App chrome (render bench)** — 8-point scale:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, swatch gaps, inline padding |
| sm | 8px | Compact control spacing, card padding, rail gaps |
| md | 16px | Default element spacing, control-to-control gaps |
| lg | 24px | Rail section padding, card section spacing |
| xl | 32px | Layout gaps between rail and canvas |
| 2xl | 48px | Major section breaks in rail |
| 3xl | 64px | Page-level spacing (canvas top margin) |

**Document (templates)** — mm scale (print units, deliberate exception to the px scale):

| Value | Usage |
|-------|-------|
| 15mm | Page block padding (ALL templates — harness geometry contract, fixed) |
| 12mm | Default section gap (header→customer→table→totals→footer) |
| 8mm | Compact section gap (within header, between blocks) |
| 4mm | Tight gaps (logo-to-name, label-to-value) |
| 6px | Table row vertical padding (all templates) |

Exceptions: document content uses mm/px print units, not the 8px app scale — required for print-CSS parity. No other exceptions (no 44px touch targets needed this phase — the bench is desktop-first; mobile builder is Phase 4).

## Typography

**App chrome** (Geist Variable, 4 sizes / 2 weights — the app contract):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 13px | 400 | 1.4 |
| Heading | 16px | 600 | 1.3 |
| Display | 20px | 600 | 1.2 |

Note: shadcn base-nova ships some components at 500 weight — inherited as-is where the component defines it (a pass-through, not a declared weight); the app chrome contract declares exactly 400 + 600.

**Document (print surface)** — deliberately differentiated type scale. Explicit exception to the app-chrome 4-size/2-weight contract, mirroring the Spacing section's mm exception:

- **Justification:** template identity differentiation (TEMP-02 — each of the 7 templates must be visually distinct at a glance) and existing harness-calibrated golden baselines (tests/fixtures/invoice-torture.preview.png — the document base must NOT move).
- **Totals (not counted against the app contract):** document base spans 11–24px at weights 400/600/700; per-template display overrides add sizes (18/20/26/28px titles, 9/10px mono labels), so the full print-surface span is 9–28px across weights 400/500/600/700 (500 appears only as the existing mono-label weight, e.g. Agency labels).
- **Document base** — inherited from current DocumentPage, harness-calibrated, do not change:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 11px | 400 | 1.5 |
| Table header | 11px | 600 | 1.4 |
| Company name | 20px | 600 | 1.2 |
| Document title | 24px | 600 | 1.2 |
| Grand total | 11px | 700 | 1.4 |

- Per-template display sizes and label treatments (headings font, title sizes, mono label sizes) are enumerated in the Template Identity section below — **those tables are the single source of truth for template type** (e.g. Minimal title 18px 600, Corporate serif company name 20px, Agency title 28px 700 + 9px/10px mono uppercase labels, Creative display serif italic 26px + 9px mono labels).

## UI Considerations

Applicable state considerations resolved: 10 covered, 3 backstops, 0 unresolved — or "none applicable" per element kind.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | logo upload (media/interactive-control) | ✅ covered | "No logo" empty state + "Add logo" affordance (copy above); preview chip renders once a data: URL is set |
| loading | print preview (static-content) | ✅ covered | Dialog shows "Preparing preview…" while the paginated page stack renders (same DOM, sync render — sub-second) |
| error | logo upload (media) | ✅ covered | Rejected file (type/size) → inline "Couldn't load that file…" message beside the control; no state change |
| error | print preview (static-content) | ✅ covered | Render failure → "Preview failed to render…" + re-render button (copy above) |
| populated | template gallery (list-collection) | ✅ covered | Fixed 7-card grid, always populated; each card = template name + 3 swatch dots (ink/primary/accent); selected = accent ring + check icon |
| populated | live preview (static-content) | ✅ covered | A4 page block centered on gray canvas with soft shadow (screen only — shadow removed in print via existing print.css) |
| long-text | document content (static-content) | 🧪 backstop | Long names/descriptions WRAP (never truncate, never ellipsis) — the torture fixture (18 items, long German→English strings) already paginates; lift as { statement: "Long text wraps and paginates identically in preview, print, and PDF", verification: backstop } — parity harness is the held-out test |
| overflow | document content (static-content) | 🧪 backstop | Content exceeding one A4 page paginates automatically (PDF-03) — existing torture-fixture ≥2-page harness test covers this; A5/A3 page sizes must paginate with the same rule |
| zero-one-many | template gallery (list-collection) | ✅ dismissed | Fixed curated set of 7 (TEMP-01) — no zero/one/many variance, singular copy never needed |
| overflow | template gallery (list-collection) | ✅ covered | Grid wraps to 2 columns inside the 320px rail; cards never scroll the rail, rail scrolls as a whole |
| loading | live preview (interactive-control) | ✅ dismissed | Rendering is synchronous React render of one component — no async fetch, no skeleton needed (offline-first, data in memory) |
| empty | document content (static-content) | ✅ covered | Blank template + no line items renders a valid empty page (structure intact, TEMP-03) — same render path, no empty-graphic or "no content" overlay needed |
| zero-one-many | document content (static-content) | ✅ covered | Single-page vs multi-page divergence is the pagination backstop above — same DOM, page stack slices it; no per-page-count special-casing in copy |
| overflow | print preview (static-content) | ✅ covered | Many pages → vertically stacked page blocks in the dialog with "Page 1 of N" counter; dialog body scrolls, footer stays fixed |
| overflow | branding header/footer (static-content) | 🧪 backstop | Long header/footer text follows the same wrap rule as document content — covered by the shared long-text backstop (parity harness is the held-out test) |
| partial | logo upload (media) | ✅ dismissed | File picked but not yet read → native input state only, sub-second synchronous read; no partial-UI needed |
| overflow | logo upload (media) | ✅ dismissed | Oversized logo constrained to fixed 48px preview chip (CSS object-fit); source image never laid out at natural size |
| long-text | logo upload (media) | ✅ dismissed | Image element — no text wrapping applies (n/a) |
| loading | template gallery (list-collection) | ✅ dismissed | Fixed static 7-card set, no fetch — rendered from a constant; nothing to load |
| error | template gallery (list-collection) | ✅ dismissed | Static curated set cannot fail to render; no error path exists |
| partial | template gallery (list-collection) | ✅ dismissed | Set is always exactly 7; no partial-render state |
| error | branding color inputs (interactive-control) | ✅ dismissed | Native `<input type="color">` constrains to valid hex — invalid input impossible; no error state needed |

The bench is the minimal UI that proves the render pipeline. It is NOT the Phase-4 builder — no inline canvas editing, no layers, no properties panel. Layout:

```
┌─────────────────────────────────────────────────────────────────┐
│ Bench header: "Paperchaser" (brand mark)      [Page size ▾] [Print preview] │
├──────────────────────────┬──────────────────────────────────────┤
│ Left rail 320px (cards): │ Center canvas (#f3f4f6):            │
│  Template gallery (7)    │   A4 page block (DocumentPage)      │
│  Branding                │   white, 15mm padding, soft shadow  │
│   · Logo                 │   centered, 64px top margin         │
│   · Primary color        │                                     │
│   · Accent color         │                                     │
│   · Heading font         │                                     │
│   · Body font            │                                     │
│   · Header style         │                                     │
│   · Footer style         │                                     │
│   · Watermark            │                                     │
│  Page size               │                                     │
└──────────────────────────┴──────────────────────────────────────┘
```

- **Live preview** = the exact `DocumentPage` component (existing, src/components/DocumentPage.tsx) re-rendered with `template` + `branding` + `pageSize` props. Parity by construction: one DOM, three projections.
- **Data source:** document loaded from Dexie repos (Phase 2) with a seeded demo document if the store is empty (planner decides seed mechanics). The `?fixture=` spike route stays for parity tests.
- **All controls apply instantly** (controlled state → re-render). No "Apply"/"Save" button — WYSIWYG.
- Bench chrome hidden under print via existing print.css (`.app-shell`, `visibility`) — no change to the print projection.

**Model fields the UI needs (planner wires into the schema — style-only, structure untouched per TEMP-03):**
`template: 'blank' | 'minimal' | 'modern' | 'corporate' | 'freelancer' | 'agency' | 'creative'`
`branding: { logo (reuse company.logo, data: URL only — T-02-02), primaryColor, accentColor, headingFont: 'geist'|'geist-mono'|'source-serif-4', bodyFont: same enum, headerStyle: 'standard'|'banner'|'compact', footerStyle: 'minimal'|'standard'|'detailed', watermark: 'auto'|'draft'|'paid' }`
`pageSize: 'a4' | 'a5' | 'a3'` (Decision 1)
Watermark TEXT derives from status (D-11: `deriveWatermark()` — never stored): `draft→DRAFT`, `paid→PAID`, `sent→none`. The `watermark` branding field only overrides auto: `'draft'` forces DRAFT, `'paid'` forces PAID.

## Branding Controls (BRND-01..06)

| Control | Type | Behavior |
|---------|------|----------|
| Logo (BRND-01) | native file input → data: URL | PNG/JPG/SVG ≤ 2 MB; preview chip 48px in the header; "Remove logo" (destructive style, confirm dialog); schema enforces data: URL (T-02-02) |
| Primary color (BRND-02) | `<input type="color">` + 4 preset swatches from active template | Applied to every template primary usage (see identity table); presets = active template's ink/primary defaults |
| Accent color (BRND-03) | `<input type="color">` + 4 presets | Applied to accent usages only |
| Fonts (BRND-04) | 2 selects: Heading font, Body font | Enum: Geist / Geist Mono / Source Serif 4 — offline-bundled (Decision 2) |
| Header style (BRND-05) | Select: Standard / Banner / Compact | 3 template-agnostic presets (below) |
| Footer style (BRND-05) | Select: Minimal / Standard / Detailed | 3 template-agnostic presets (below) |
| Watermark (BRND-06) | Radio: Auto (from status) / Draft / Paid | Default Auto (D-11 derivation); "Draft" forces DRAFT, "Paid" forces PAID; render = existing `.watermark` overlay (64px, rotate −30°, opacity 0.15, accent color) |

**Header presets (template-agnostic, color/type inherited from template + branding):**
- **Standard** — split layout: company block left (logo + name + address), title + meta right-aligned. Default for Minimal/Corporate/Freelancer/Creative.
- **Banner** — full-width band in primary color, white content: company name left, title right. Default for Modern/Agency.
- **Compact** — single line: logo + company name left, title + number + date right, hairline rule below. Default for Blank.

**Footer presets:**
- **Minimal** — one small gray line (thanks/payment blurb). Default for Blank/Minimal/Modern.
- **Standard** — hairline rule + 2-line blurb (payment instructions + thanks). Default for Freelancer/Creative.
- **Detailed** — double rule + label-value grid (bank details, payment instructions) + small print. Default for Corporate/Agency.

<objective>
Build the single-document JSON import/export boundary: `exportDocument` wraps a document in the versioned envelope and validates before serializing (STOR-03); `parseDocument` validates untrusted JSON in three stages — JSON syntax, envelope literals, document schema — returning structured rejection reasons `{ code, path, expected, received }` so future UI (Phase 6 backup/restore) renders copy without re-deriving it (STOR-04, D-13/D-14, UI-SPEC E1).

Purpose: This is the phase's only untrusted-input surface. The boundary is strict on shape (reject malformed/schema-invalid imports) and strips unknowns (D-14), per the locked decision: missing/extra data never silently corrupts a document. The envelope is the migration seam for future schema evolution and is re-used by Phase 6 workspace backup/restore (CONTEXT.md Integration Points).

Output: `io.ts` (envelopeSchema + exportDocument + parseDocument + ImportError union) and `io.test.ts` (lossless round-trip + boundary-rejection fixtures).
</objective>

<task type="auto">
  <name>Task 2: Fix removeChild crash on blur for all toolbar actions (G-04-07)</name>
  <files>src/components/edit/RichTextCell.tsx, src/components/DocumentPage.tsx</files>
  <read_first>
  Root cause: RichTextCell renders <div contentEditable><AstView value={text} /></div> where AstView is React children. execCommand mutates DOM (adds <strong>/<ul>/<a>) then blur does domToAst + onCommit which re-renders DocumentPage. DocumentPage keys are getPlainText(item.title) so formatting-only change keeps key, React diffs mutated DOM vs expected AstView and throws removeChild. Fix minimal:
  - Change DocumentPage keys to JSON.stringify(text) or JSON.stringify(doc) so any AST change (marks or list wrapping) changes key and forces remount, avoiding diff.
  - In RichTextCell, make commit defer via requestAnimationFrame or queue after execCommand settles: `requestAnimationFrame(() => { const doc = domToAst(ref.current); onCommit(doc) })` to ensure DOM is stable before reading.
  - Make RichTextCell truly uncontrolled while focused: do not re-render AstView inside while focused is true; instead use ref.current.textContent/innerHTML managed imperatively, and only render AstView when !focused. Suppress React reconciliation during editing.
  - Add minimal error boundary around DocumentPage row to prevent full app crash on future removeChild (ponytail: try/catch around domToAst).
  Test: select, click List, blur -> no crash, list persists after re-focus.
  </read_first>
  <action>Fix DocumentPage keys to include AST JSON, defer RichTextCell commit to next frame, make contentEditable uncontrolled while focused to avoid React vs execCommand race, add boundary.</action>

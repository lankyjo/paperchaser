# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope:** Three-pane WYSIWYG builder (BUIL-01..09, LINE-01, LINE-02). Inline canvas editing (D-01..D-11), model-snapshot undo/redo + debounced auto-save (D-12..D-18), desktop/mobile layout with bottom sheets (D-19..D-24), implicit-section outline with line-item reorder + block visibility (D-25..D-30). Sits ON TOP of the parity-proven DocumentPage (ADR 0002). **The product's core promise — identical preview/output — must never break: all editing chrome is screen-only overlay in the builder shell, never inside `#print-root` (D-04, D-11).**

**Hard boundary (parity):** this phase reuses Phase 3's entire design system verbatim (tokens, spacing, typography, color, document mm scale, template identities). Nothing in Phase 3's contract is renegotiated; this spec only ADDS the builder shell, editing surfaces, and their states.

## Typography

**App chrome** (Geist Variable, 4 sizes / 2 weights — Phase 3 contract CONTINUES):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 13px | 400 | 1.4 |
| Heading | 16px | 600 | 1.3 |
| Display | 20px | 600 | 1.2 |

**New this phase — editing surfaces (all within the 4-size/2-weight contract):**

| Surface | Size | Weight | Notes |
|---------|------|--------|-------|
| Floating toolbar buttons | 14px | 400 | Icon-only (16px icons), aria-labels; active format = 600 via `--primary` text |
| Empty-cell placeholder | inherits cell | 400 | Muted italic (`--muted-foreground`), shown via `:empty` + `data-placeholder`, NEVER in print (D-11) |
| Save indicator | 13px | 400 | "Saved" muted / "Saving…" muted / failure uses badge (destructive) |
| Outline item text | 13px | 400 / 600 selected | Truncate with ellipsis (screen-only, full text on canvas) |
| Sheet header | 16px | 600 | Mobile bottom-sheet titles |

**Document (print surface):** type scale UNCHANGED from Phase 3 — 9–28px per-template, harness-calibrated golden baselines must NOT move. Rich text (bold/italic/underline/list/link, D-08) uses weight/style variation of the SAME fonts — bold = weight 600 (or 700 where the template declares it), italic = the template's italic face (Geist has no true italic — use `font-style: italic` synthesis; Source Serif 4 has real italics), underline = text-decoration, link = the template's primary/accent color. No new sizes, no headings/alignment/colors (D-08).

## Color

**App chrome** — Phase 3 neutral contract CONTINUES; `--primary` near-black (oklch(0.205 0 0)) is the **editing accent**:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #f3f4f6 (shell background) | Builder backdrop, canvas surround, rail background |
| Secondary (30%) | #ffffff (cards/panels) | Panes, floating toolbar, popover, sheets, save badge surface |
| Accent (10%) | shadcn `--primary` (oklch(0.205 0 0)) | Selection ring, drop indicator, focused-cell ring, active outline item, active format (B/I/U) in toolbar, visibility toggle on-state |
| Ring | shadcn `--ring` (oklch(0.708 0 0)) | Hover outline on editable cells (subtle — never confused with selection) |
| Destructive | shadcn `--destructive` (oklch(0.577 0.245 27.325)) | Invalid numeric cell ring, delete-item controls, save-failure badge |

Accent reserved for: **selection ring, drop indicator line, focused-cell ring, active outline item, active rich-text format, visibility-toggle on-state** — never decorative fills, never background tints in the builder chrome. Hover states use `--ring` or `--muted-foreground`, NOT accent, so selection is always distinguishable from hover.

**Document:** white page always; template palettes + branding overrides UNCHANGED (Phase 3 identity tables are the single source of truth). Editing chrome colors above live in the builder shell, never inside `#print-root`.

## Copywriting Contract

English throughout (Phase 3 language decision holds). Editing is direct manipulation — there is no single "primary CTA" button; the primary action is clicking a cell and typing. The header keeps the Phase 3 "Print preview" CTA.

| Element | Copy |
|---------|------|
| Header actions | "Print preview" (existing, BUIL-10), undo/redo icon buttons if planner adds them (D-18 discretion) with tooltips "Undo" / "Redo" |
| Empty state — line items | Heading: "No items yet". Body: "Add your first line item to start the table." Action: "Add item" button (accent-styled, placed where the table's first row would be and in the outline pane) |
| Empty state — outline blocks | Not applicable — the 5 fixed blocks (Header, Bill to, Items, Totals, Footer) are always listed (D-25/D-27); only the line-items list under Items can be empty (dismissed, see UI Considerations) |
| Empty cell placeholder | "Type here" — muted italic in the editable cell; shows only while the cell is empty, NEVER in print (D-11 parity guard) |
| Error state — invalid number | Inline ring + popover: "Enter a valid number." (negative, NaN, or non-decimal per CURRENCY_DECIMALS — D-09) |
| Error state — save failure | Toast: "Couldn't save your changes. They're kept here — retry now." Actions: "Retry" (primary) / dismiss. Unsaved badge appears in header: "Not saved" |
| Save indicator | "Saved" (idle, muted) / "Saving…" (in-flight, muted) / failure = destructive "Not saved" badge + toast (D-16/D-17) |
| Destructive confirmation — delete line item | "Delete item?" — "Removes {title or 'this item'} and its amount from the totals." Actions: "Delete" (destructive) / "Cancel" |
| Destructive confirmation — remove link | In the link popover, "Remove link" (destructive text button) — no confirmation (reversible via undo) |
| Link editor (floating toolbar) | Label "Link", input placeholder "https://example.com", actions "Apply link" (primary) / "Remove link" (destructive) |
| Block visibility toggle | Toggle labeled with block name, e.g. "Show footer"; off-state hides the block on canvas and print (persisted per-document, D-30). No confirmation — instant + undoable |
| Undo/redo empty history | No UI: shortcuts no-op silently (D-18); if buttons added, disabled state (dismissed, see UI Considerations) |

## UI Considerations

Applicable state considerations resolved: 12 covered, 2 backstops, 0 unresolved — or "none applicable" per element kind.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | line items (list-collection) | ✅ covered | Zero items → "No items yet" copy + "Add item" button; the Items block still renders its header row so the canvas never looks broken (LINE-03 totals still compute to zero) |
| zero-one-many | line items (list-collection) | ✅ covered | Singular/plural copy handled by neutral phrasing ("items"); one row = normal table render, many rows = pagination backstop below; no special-casing |
| overflow | line items / outline (list-collection) | ✅ covered | Outline pane scrolls as a unit (Phase 3 rail pattern); line-item list inside Items block paginates per the document backstop; outline rows truncate with ellipsis (full text visible on canvas) |
| long-text | outline items (nav/list) | ✅ covered | Outline row text truncates with ellipsis (screen-only); the canvas cell itself wraps — full content always editable in place |
| long-text | canvas cells (interactive-control) | 🧪 backstop | Rich-text cells WRAP and paginate identically in preview/print/PDF — the existing torture-fixture parity harness is the held-out test; new: it must run against the edit-mode DOM (D-11) so long edited text is covered |
| empty | canvas cells (interactive-control) | ✅ covered | Empty cell → "Type here" placeholder via `:empty` + `data-placeholder`; placeholder is screen-only, print projection shows a clean empty cell (D-11 spec asserts no editing artifacts in print) |
| error | numeric cells (form) | ✅ covered | Invalid input → destructive ring + "Enter a valid number." popover; commit is blocked until valid or Escape cancels (D-09/D-10) |
| loading | save indicator (interactive-control) | ✅ covered | "Saving…" state while the debounced write is in flight (~800ms window, D-15); synchronous local render — no skeleton needed anywhere in the builder |
| error | save indicator (interactive-control) | ✅ covered | Failure → "Not saved" badge + toast with Retry; in-memory model never discarded (D-17) |
| empty | undo/redo (interactive-control) | ✅ dismissed | Empty history → shortcuts no-op (D-18); no visual state needed. If planner adds header buttons, disabled state (muted, aria-disabled) |
| overflow | floating toolbar (interactive-control) | ✅ covered | Toolbar flips BELOW the selected cell when it would clip the viewport top; clamped horizontally to the viewport (16px margins); never overlays the header save state |
| populated | floating toolbar (interactive-control) | ✅ covered | Renders only while a rich-text cell is focused/selected (D-05); hidden on blur commit — matches "chrome appears on interaction" (D-03) |
| overflow | zoom controls (interactive-control) | ✅ covered | Zoom bounded (desktop-only, D-24); buttons disabled at min/max bounds; percent display shows current scale |
| overflow | mobile sheets (form) | ✅ covered | Sheet content scrolls internally (react-spring-bottom-sheet scroll-locking); sticky sheet header/footer per library contract; keyboard resize handled via RESIZE event |
| long-text | mobile sheets (form) | ✅ covered | Sheet rows inherit the 44px touch-target contract and wrap; description field is a taller multi-line surface inside the sheet |
| partial | outline visibility (list-collection) | ✅ covered | Per-block toggle reflects model state; hidden block shows muted row + toggle off; canvas and print skip the block (D-30), outline still lists it so the user can restore |
| loading | canvas (static-content) | ✅ dismissed | Synchronous React render of one component — no fetch, no skeleton (same as Phase 3) |
| error | canvas (static-content) | ✅ dismissed | Same render path as Phase 3 — render failure handled by the existing preview error copy (Phase 3 contract), not a new state |

│  · Footer     │                                  │                           │

- **Left rail = section outline (D-25..D-28):** lists the 5 fixed blocks (Header, Bill to, Items, Totals, Footer) as virtual entries + each line item nested under Items. ## Editing Chrome Overlay Contract (D-03, D-04, D-11 — the parity-critical section)

All editing chrome is absolutely-positioned overlay in the builder shell, keyed to element bounding rects via refs. **Nothing below ever renders inside `#print-root`.** The parity harness asserts edit-mode DOM == view DOM and that the print projection carries no editing artifacts (no caret, no outline, no placeholder).

| Chrome | When | Visual | Interaction |
|--------|------|--------|-------------|
| Hover outline | Pointer over an editable cell | 1px solid `--ring` box around the cell | Pointer cursor; no other effect — hover must not disturb layout |
| Selection ring | Cell focused/selected | 2px solid `--primary` + 2px white gap | Marks the active edit target; clicking an empty cell focuses it and shows the "Type here" placeholder |
| Editing state | While contentEditable is active | Selection ring persists + caret visible | Caret managed by the contentEditable controller (D-01); cell keyed by field so caret survives re-render on commit (D-10) |
| Drag handle | Hover/selection on a reorderable cell or outline item | 20×20px grip icon (`--muted-foreground`) at cell edge (line items, canvas) / row edge (outline) | Drag start → reorder mode (desktop only, D-24); keyboard fallback via outline (move up/down) |
| Drop indicator | Dragging over a valid target | 2px `--primary` horizontal line + 16px chevron between rows | Only rendered over valid drop targets; invalid targets show no indicator (system cursor shows not-allowed) |
| Floating toolbar | Rich-text cell focused with selection | White card, shadow, radius (Phase 3 card style), 32px offset above the selection | B / I / U / bulleted-list / link buttons; active format = `--primary` icon + 600 weight; flips below on viewport clip; hides on blur commit |
| Invalid ring | Numeric cell with invalid input | 1.5px `--destructive` ring + popover | Popover: "Enter a valid number."; commit blocked until valid; Escape restores previous value and cancels (D-10) |
| Placeholder | Empty editable cell | "Type here" muted italic via `:empty` + `data-placeholder` | Disappears the moment the user types; NEVER printed (D-11) |

**Floating toolbar contents (D-05/D-08, minimal format set):** Bold, Italic, Underline, Bulleted list, Link. No headings/colors/alignment. Toolbar buttons are icon-only (lucide: Bold, Italic, Underline, List, Link), 16px icons, aria-labels, tooltip on hover. Link opens the popover (input + Apply/Remove). Toolbar is a shell overlay — it does not touch the document DOM.

**Numeric cell contract (D-09):** contentEditable-but-filtered — `inputMode="decimal"`, keystroke filter (digits, one decimal separator, minus), parse-to-minor-units on commit via `money.ts` primitives (never floats), inline validation on invalid → destructive ring + popover fallback for edge cases (negative, NaN, JPY 0dp). Commit on blur/Enter; Escape cancels.

**Keyboard contract (D-10, D-18):**

| Key | Behavior |
|-----|----------|
| Enter | Commit cell (numeric) / new line (rich text: Shift+Enter = newline within list) |
| Escape | Cancel edit, restore prior value |
| Tab / Shift+Tab | Commit + move focus to next/previous cell (document field order) |
| Ctrl/Cmd+Z | Undo (native shortcut) |
| Ctrl/Cmd+Shift+Z or Ctrl/Cmd+Y | Redo (native shortcut) |
| Ctrl/Cmd+B/I/U | Bold / Italic / Underline in rich-text cells (native) |

## Save & Undo Surface (D-12..D-18)

- **Save indicator (header):** three states — "Saved" (muted), "Saving…" (muted, while debounced write in flight, ~800ms after last change), "Not saved" (destructive badge, on failure). In-memory model is never discarded on failure (D-17). Retry via toast action or next edit.
- **Undo/redo (D-12..D-14):** model-snapshot history, bounded ~50 snapshots. Each committed edit (blur/Enter) is one undo step (D-13) — including text edits, line-item CRUD/reorder, template/branding/page-size changes. Triggered by native shortcuts only (D-18); header icon buttons at planner discretion (disabled when history empty).
- **Toast:** shadcn toast or minimal custom (planner discretion — NOT a registry block if custom); appears bottom-right on desktop, top (below header) on mobile. Only for save failure in this phase.

## Mobile Interaction Contract (<1024px, D-20..D-24)

Layout stacks vertically: **top header (back, undo/redo, save indicator, preview toggle) + sticky live preview on top + editor surface below.** Same editing surfaces, touch-adapted:

- **Single breakpoint (D-22):** <1024px = stacked mobile layout; ≥1024px = three-pane. No intermediate breakpoints.
- **Sticky live preview (D-20/D-24):** the SAME DocumentPage rendered at **fit-width** (auto-scale to viewport width, browser pinch-zoom allowed). Canvas zoom is desktop-only.
- **Editor surface below:** each block/row is a tappable row; tapping opens its properties in a **bottom sheet** (D-20).
- **All sheets/drawers = bottom-sheet semantics (library-agnostic contract, D-21):** slides up from bottom, drag handle on top, backdrop dim, tap-backdrop dismiss, Escape dismiss, snap points (content-min / 92% or full), internal scroll with scroll-locking, focus trap + aria-hidden on the rest of the page, safe-area insets for iOS. Content: sticky header (title + done), scrollable body (form rows, 44px targets), optional footer.
- **Reorder on touch (D-23):** **up/down controls** (icon buttons per row in the sheet/outline) — never drag-and-drop on touch (avoids drag-vs-scroll conflict). Drag-and-drop remains desktop-only.
- **Numeric cells on mobile:** same inline filtering; the popover fallback becomes part of the sheet row (or a small popover — planner discretion), never a second full-screen layer.
- **Save failure toast on mobile:** rendered below the sticky header so the preview toggle stays reachable.

**The mobile sub-spec (04-MOBILE-SPEC.md, D-19) is a separate planner artifact** — this contract fixes the interaction semantics above; the sub-spec owns the detailed mobile screen inventory.

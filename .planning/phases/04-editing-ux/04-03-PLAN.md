=== RICHTEXTCELL ENHANCEMENT (MODIFY) ===
Extend the tracer's plain-text RichTextCell with full formatting per D-05/D-08:

Formatting via execCommand (RESEARCH Code Example, lines 434-437 — deprecated but universally supported, preserves undo buffer):
- Expose a formatting API: formatBold(), formatItalic(), formatUnderline(), formatList(), setLink(href)
- execCommand('bold') / ('italic') / ('underline') / ('insertUnorderedList') applied to the focused contentEditable container
- Link: wrap selected range in <a href={href}> via manual range manipulation (execCommand('createLink') is unreliable cross-browser). Use Selection API + Range.surroundContents().
- Active-format detection: on selection change, read queryCommandState('bold'/'italic'/'underline'/'insertUnorderedList') to set active state for the toolbar.
- Link detection: check if the selection's commonAncestorContainer is inside an <a> element.

DOM→AST serializer (domToAst, in richtext.ts):
- Traverse the contentEditable container's childNodes recursively
- Whitelist by tag name: B/STRONG → bold mark, I/EM → italic mark, U → underline mark, UL>LI → list+listItem nodes, A → link mark with href (run through isSafeHref)
- Text nodes → text AST node (without marks if parent has no matching tag, with marks if wrapped)
- Collapse whitespace: multiple spaces → single space, leading/trailing trim
- Unknown tags → unwrap to text content (never passthrough — RESEARCH Pitfall 2)
- Unit-test against a matrix of browser-shaped DOM strings (fixture strings, not real browsers — RESEARCH Pitfall 2 warning signs)

Paste interceptor:
- onPaste handler: e.preventDefault(), read e.clipboardData.getData('text/plain'), insert at cursor via execCommand('insertText', false, plainText)
- v1 policy: strip ALL formatting on paste (RESEARCH Pitfall 2, lines 285-287). Formatting is toolbar-driven per D-08.

- render via CSS :empty pseudo-class + data-placeholder attribute: content: attr(data-placeholder)
- Show "Type here" muted italic (UI-SPEC §Editing Chrome, line 215)

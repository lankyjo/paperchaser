=== RICHTEXTCELL (NEW: src/components/edit/RichTextCell.tsx) ===
Uncontrolled contentEditable — plain text ONLY in this tracer (no formatting). Core pattern per RESEARCH Pattern 1 (lines 238-264):
- Props: { text: string, onCommit: (text: string) => void }
- useRef<HTMLDivElement> for the editable container
- Render: <div ref={ref} contentEditable suppressContentEditableWarning onBlur={commit} onKeyDown={handleEscape}>
- While focused: NO re-render from model (uncontrolled). The component should NOT accept a changing `text` prop while focused — use a keyed remount on commit (D-10: cells keyed by field so caret survives re-render after commit).
- commit(): read ref.current.textContent, call onCommit
- Escape: re-render from model (parent remounts with key)
- D-11: this cell renders on the SAME DOM the view uses. The inner content is the exact text that DocumentPage already renders for {model.customer.name}.
- In the tracer: render the shared AstView for single-paragraph/single-text ASTs — unwrap the AST and display textContent. Later plans add formatting.
- Anti-patterns: NEVER use dangerouslySetInnerHTML. NEVER update props while focused. NEVER register window event listeners directly (use builder-root onKeyDown for undo/redo shortcuts per D-18).

=== USEHISTORY (NEW: src/components/edit/useHistory.ts) ===
Model-snapshot history + debounced auto-save. Pattern per RESEARCH Pattern 2 (lines 394-422), zero useEffect:
- Exports: useHistory(initial: DocumentModel) → { model, setModel, commit, undo, redo, saveState, retrySave }
- past/future: useRef<DocumentModel[]>([])
- saveState: useState<'saved' | 'saving' | 'failed'>('saved')
- debounce timer: useRef<ReturnType<typeof setTimeout>>()
- commit(next): push current model to past (slice(-49) to bound at 50, D-14), clear future, setModel(next), scheduleSave(next)
- undo: pop from past, push current to future, setModel
- redo: pop from future (Ctrl+Shift+Z or Ctrl+Y, D-18)
- scheduleSave: clearTimeout + setTimeout(800ms) calling documentsRepo.put, setSaveState('saving'→'saved' on success, 'failed' on error)
- retrySave: re-run documentsRepo.put on current model
- Keyboard shortcuts: bind to builder-root onKeyDown — Ctrl/Cmd+Z → undo, Ctrl/Cmd+Shift+Z → redo. NO window event listeners. NO useEffect.
- On new commit while saveState is 'failed': clear failed state, scheduleSave again (D-17: model never discarded).
- State type precedent (BrandingPanel.tsx:71): "useState<'saved' | 'saving' | 'failed'>('saved')" mirrors "useState<'logo' | 'reset' | null>(null)"

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| contentEditable DOM→AST | User-modified DOM serialized to AST on commit — must not inject arbitrary HTML |
| BuilderShell→DocumentPage | Edit mode prop crosses into the shared render component — must not affect print projection |
| Auto-save→Dexie | Debounced document model written to IndexedDB — must never discard in-memory model on failure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Tampering | RichTextCell contentEditable→AST serialization | medium | mitigate | Serialize textContent (not innerHTML) — no HTML passthrough. Paste policy strips to plain text (v1). AstView renders React elements only. |
| T-04-07 | Information disclosure | contentEditable paste | medium | mitigate | Paste event intercepted: e.preventDefault(), insert plain text only via execCommand('insertText') — no rich HTML injection surface. |
| T-04-08 | Elevation of privilege | D-11 edit attrs | low | accept | contentEditable attribute on cells in print media is structurally asserted absent in parity spec. Print is a separate projection — editing attrs do not affect printed output. |
| T-04-09 | DoS | useHistory unbounded snapshots | low | accept | History bounded to 50 snapshots (slice(-49), D-14). Each snapshot is a cloned DocumentModel — bounded memory growth by construction. |
